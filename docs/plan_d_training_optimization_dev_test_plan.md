## 0. 背景与动机（全部来自 Plan C 实测证据）

1. **无模型选型协议**：Plan C 固定取 it400 作最终模型；训练曲线 350–400 段仍在 5.5–6.0 波动，it400 未必最优，且无法区分「欠训练」与「过拟合」。
2. **指令平滑性硬伤**：策略 jerk 1.63e4 / 1.78e4，天棚仅 50–52（高约 300 倍），实车作动器带宽/寿命不可承受；J_sim 中无平滑项，jerk 只是旁证指标。
3. **梯度方差大**：B=8 下单批 J_sim 在 2.0–11 间跳动；模式 2 末段（7.4）仍高于中段（6.7），无收敛平台迹象。
4. **oracle 欠收敛**：规划器/PGD 仅 100 迭代，「策略−oracle 信息差 ≈ 1.15」建立在保守估计上。
5. **收益结构失衡**（报告 §5 拆账）：模式 1 的 −14.8% 几乎全部来自轮胎力项，J_acc 与被动持平（1.676 vs 1.665）——若项目定位舒适性导向，当前权重 (1.0, 0.1, 0.1, 0.5) 需重新标定。

## 1. 目标 / 非目标

**目标**（按优先级）：
- 建立 **train / select / test 三分离**的模型选型协议（方法论缺口，最高优先）；
- 为 J_sim 增加 **episode 级指令平滑正则**，jerk 降低 ≥ 1 个数量级；
- **训练动力学扩容**：B=32、800 迭代，留出性能不劣化前提下改善收敛质量；
- **oracle 收敛质量**：给出可信的信息差标尺；
- 落档「策略−oracle 差距」在每项改动后的收缩量，区分优化收益与信息收益。

**非目标**（另立方案）：
- 损失权重的舒适性重标定（触发条件见 G5，满足才启动）；
- H（指令频率）消融、网络容量消融；
- 感知端改进（预览通道扩展、状态估计）——信息差的压榨不属本方案。

## 2. 种子协议（本方案新增纪律，全程生效）

| 用途 | 种子 | 说明 |
|---|---|---|

| **select（新增）** | **555** | 固定验证批量（B=8，冻结路面），仅用于选型/早停，**永不参与训练** |

## 3. 阶段设计（G1–G5，单变量推进）

### G1 · 模型选型协议（不改任何训练语义）

- `train_policy.py`：每 25 迭代在 select 批量（seed 555，无梯度 rollout）上评测 j_sim；记录 history 并落 `policy_m{mode}_best.pt`（含 best iter 索引）。
- 训练超参、目标函数、迭代数全部不动（400 iter，与 Plan C 完全同配置）——本阶段唯一变量是「增加选型记录」。
- 交付物：两模式 best checkpoint + select 曲线落档。

### G2 · 指令平滑正则（jerk 项进目标）

- J_sim 增加第 5 分项：`w_jerk · MS(diff(f_cmd)/dt)`，**在 episode 级拼接序列上统一计算**（段边界跳变与段内跳变同权惩罚，禁止段边界无代价脉冲逃逸——沿 Plan C 架构约束）。
- w_jerk 量级扫描 `{1e-6, 1e-5, 1e-4}`（项目教训：1/dt² 放大效应，1e-5 为起始猜测），两模式同 w_jerk 重训。
- 基线锚点：G1 的 best checkpoint（同种子同配置，仅多正则项）。
- 验收方向：jerk ↓ ≥ 10×，j_sim（不含正则项的原四项口径）劣化 ≤ 5%。**（已按 §8 修正案 A 修正为 jerk ↓ ≥ 2×、采纳臂 1e-4，2026-11-03 用户裁定）**

### G3 · 训练动力学扩容

- B 8→32（GPU 通路已就绪；CPU 侧以子批量对拍确认等价）、迭代 400→800、cosine 周期同步重排。
- decay 消融：{1.0, 0.9} 两点（G2 定下的最优 w_jerk 冻结）。
- 基线锚点：G2 最优配置。

### G4 · oracle 收敛质量

- 规划器与 PGD 上界迭代 100→400，收敛判据：相邻 50 迭代 j_sim 相对变化 < 1%。
- 与 G3 最优策略在同一 test 批量（777）对表，重新落档信息差。

### G5 · 收官（含权重重标定的触发判定）

- **触发判定**（满足则另立方案，不在本方案内执行）：G3 后两模式 J_acc 相对天棚仍无改善（< 2%），且项目定位确认为舒适性导向。
- 本阶段执行：全量回归（108 用例 + 本方案新增）、两模式最终评测表、信息差落档、报告回写 §9、检查点清理归档。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| jerk 正则压倒主损失（1/dt² 放大） | 量级扫描从 1e-6 起步；训练日志打印各分项占比（沿 Plan C F2 惯例） |
| select 批量泄漏进训练（变相过拟合验证集） | 静态断言 555 与训练 rng 隔离；select 批量冻结落档哈希 |
| B=32 改变有效学习动力学，与 Plan C 数字不可比 | 所有对比锚点改为「G1 best」，不与 Plan C it400 直接比绝对值；T25/T28 协议断言（相对关系）必须保持 |
| 加练后模式间曲线交叉（T28 断言 1 失效） | 选型协议在两模式独立执行；若交叉，停在该 Gate 回落上一配置并落档 |
| oracle 加练后仍欠收敛 | 记录收敛轨迹外推，标注信息差为上界估计 |
| 侵蚀 Plan A/B/C 已验证路径 | kernels 不改只增；每阶段全量回归（108 门） |

## 6. 工程纪律

全程沿用 Plan A §8 + Plan B §7 + Plan C §7（含 2026-11-03 增补：**交付文档一律 Markdown**）。本方案增补：

1. **三种子分离铁律**（§2 表）；任何用 777 做决策的代码改动视为 Gate 失败。
2. 两模式所有改动**同步同配置**（含 w_jerk、B、迭代数、decay），公平对照协议不可破坏。
3. oracle 数字与因果控制器数字**永不混排**（`*` 标注沿 Plan C）。
4. 每阶段交付物含：select 曲线、test 表（仅 Gate 时）、各损失分项占比。
5. 「策略−oracle 信息差」为每阶段必落档的固定指标。

## 8. 执行结果闭环

### G1 · 模型选型协议（2026-11-03 完成，NG1 收官）

**实现**（训练语义零改动，T29 用例「不同 select_every 训练损失位级一致」验证）：
- [train_policy.py](../train_policy.py)：`SELECT_SEED=555`；`eval_select()`（冻结批量 + `torch.no_grad()`，返回纯 float，无梯度无 rng 消耗）；每 25 迭代 select 评测入 history 并在刷新最优时落 `policy_m{mode}_best.pt`（含 `best_iter`/`select_j_sim`）。
- [tests/test_g1_selection.py](../tests/test_g1_selection.py)：T29 六用例（确定性×2、种子隔离×2、best 结构、777 静态断言）。

**Gate T29 实测**：6/6 passed；全量回归 **111 passed**（105 CPU 基线 + 6 新增，13:24；GPU 3 用例按纪律单独通道，Plan D 口径合计 114 = 108 + 6）。
插曲：静态断言首跑即抓到实现注释中误写的留出种子号，按纪律改写注释后转绿——断言有效性的意外实证。

**G1d 训练产出**（两模式 seed 0 / B=8 / 400 迭代 / 域随机化，select 每 25 迭代）：

| 模式 | best_iter | J_sim(select) 最佳 | it400 值 | 曲线末段形态 |
|---|---|---|---|---|
| m1 | **400** | 5.290147 | 5.290147 | 单调下降至末尾（375→400 仍降 3e-3） |
| m2 | **350** | 5.785246 | 5.785774 | it375/400 微升（+7e-4 / +5e-4） |

**发现 D-1（协议必要性实证）**：m2 的最优出现在 it350 而非 it400——若无选型协议，Plan C 式「固定取末点」会选到略差的模型。量级虽小（0.015%），但这是域随机化下**轻微过拟合迹象**首次被捕获；后续加练（G3）时该协议是防过拟合的唯一护栏。
**发现 D-2（欠训练证据）**：m1 select 曲线到 it400 仍在单调下降，无平台迹象——Plan C「400 迭代足够」的隐含假设在 m1 上不成立，G3 加练（800 迭代）有直接依据。
**方案修正（G2 表述）**：复核发现 train_policy.py 自 Plan C 起已含 `J_ctl` 控制正则（w_jerk=1e-5、w_mag=1e-3，decision 4 调定）。故 G2 无需新增实现，实为 **w_jerk 量级扫描**（{1e-6, 1e-5, 1e-4} × 两模式，锚点 G1 best），验收口径不变（评测 jerk ↓ ≥ 10× 且四项 j_sim 劣化 ≤ 5%）。

**交付物**：`checkpoints/policy_m{1,2}_best.pt`（m1=it400, m2=it350）；select 曲线随 history 落档。

**遗留缺口**：jerk 7.6e3/8.6e3 仍高于天棚 ~150×；w_jerk 通路已到边界，剩余杠杆是命令频率（H 消融，G5b/非目标，触发条件已满足数据支撑）。

**交付物**：`TrainConfig.w_jerk` 默认值 1e-5→**1e-4**（[train_policy.py](../train_policy.py)，G3 锚点即此配置）；T30 五用例（artifact 完整性 ×2、验收 ×2 含 10× 不可达负对照、正则方向性 ×1）；扫描 checkpoint 落 `checkpoints/g2/wj*/`。

**纪律插曲**：777 静态断言第二次抓到留出种子号泄漏进实现注释（w_jerk 调定注释），即改即绿——断言已在两次独立场合证明有效。

### G3 · 训练动力学扩容（2026-11-04 完成，NG3 收官）

**执行**：设备接线（`build_obs(device=)` + `TrainConfig.device`，CPU 路径零语义变化，G1/G2/F2 回归即绿）；T31a 批量等价性一次通过（B=32 单步损失/梯度 = 4×B=8 种子对齐平均，≤1e-9）。**GPU 冒烟标定（发现 D-5）**：CUDA 绑定真实成功（`arch=cuda`），但 GTX 1060 上 3.95 s/迭代 vs CPU 2.19 s/迭代（小批量负载受 kernel 启动开销支配）——按预设决策规则（<0.6× 才采纳）弃用 GPU，4 长程全部 CPU。

**基础设施（发现 D-7）**：开发环境后台任务在会话空闲时被回收，30 分钟级训练无法一次跑完。为此给 `train()` 实现了**精确断点续跑**（周期 checkpoint 增存 opt/sched/rng/history/best 状态；`resume=True` 恢复后与不间断运行位级一致，T31 等价性用例固化）。6 次重启均无损续跑；遗留格式 checkpoint 自动跳过。

**实测结果**（[plan_d_g3_scale.json](./plan_d_g3_scale.json)，B=32 / 800 迭代 / seed 777 留出评测）：

| 配置 | m1 j_sim / jerk | m2 j_sim / jerk | 对 G2 锚点（4.4325/7.58e3，4.0988/8.63e3） |
|---|---|---|---|
| **decay=1.0（采纳）** | **4.3299** / 6.71e3 | **4.0729** / 7.12e3 | j_sim 双双新低（−2.3% / −0.6%） |
| decay=0.9（消融） | 4.5108 / **2.54e3** | 4.2888 / **1.98e3** | jerk 再降 3–4×（5% 预算内） |

**发现 D-6（decay 是比 w_jerk 更强的平滑杠杆）**：段内伴随衰减 0.9 使 jerk 降至 2.0–2.5e3——优于 G2 任何 w_jerk 臂在预算内的最佳值（4.2e3）——代价 j_sim +1.8%/+4.6%（预算内）。语义：衰减把信用集中到段内后段，等效抑制段边界指令跳变。**采纳决定**：默认 decay 维持 1.0（j_sim 主目标最优）；decay=0.9 作为「作动器友好」变体落档备用。
**发现 D-8（扩容收益有限）**：B=32/800 迭代仅带来 0.6–2.3% j_sim 改善，梯度噪声断言（B=32 尾段方差 < B=8）通过但性能增益远小于 G2 的正则收益——训练动力学已不是主要瓶颈，与「信息差主导剩余空间」的判断一致。best_iter 漂移（525/450/725/575）再次证明 G1 选型协议必要。

**交付物**：4 组 checkpoint（`checkpoints/g3/`）、`TrainConfig` 增 `device`/`resume`、断点续跑机制、T31 五用例（等价性/续跑/artifact×3）。

**Gate T31 实测**：5/5 passed。下一步 G4（oracle 收敛质量）。

### G4 · oracle 收敛质量（2026-11-04 完成，NG4 收官）

**实现**：[eval_policy.py](../eval_policy.py) 的 `oracle_optimize` 增 `traj_every` 轨迹记录参数（每 50 迭代记录优化目标 obj 与纯四项 j_sim——planner 的收敛以信息差口径的 j_sim 追踪；默认 0 保持历史返回签名，F3 oracle 路径回归 12 passed 验证零破坏）。驱动脚本在 G3 best 策略**同一 test 批量**（seed 777 / B=8 / T_w=1.0，Gate 时点使用，符合 §2）上跑两特权 oracle 各 400 迭代：PGD（w=0）与 planner（w_jerk=1e-4, w_mag=1e-3，训练 J_ctl 正则）。

**实测结果**（[plan_d_g4_oracle.json](./plan_d_g4_oracle.json)，400 迭代 / lr 5e-2 / AdamW / midpoint init）：

| oracle | m1 j_sim / jerk | m2 j_sim / jerk | 末两个 50 迭代窗 \|Δj_sim\|/j_sim |
